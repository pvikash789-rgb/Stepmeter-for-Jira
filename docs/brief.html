Wasted steps in Jira automation

From 3 December, every automation step has a price. Admins can already see which flows use the most steps. They can't see how many of those steps did nothing, why, or what to change.

What I tested

I built a Jira test site with 9 automation flows, each built to show one cost pattern: a broad trigger, a narrow trigger, a branch over sub-tasks, a daily scheduled search, a failing web request, and a flow that edits before it checks. For every run, I wrote down a step prediction before the Usage tab reported it.

What I found

  1. Waste is easy to miss. A flow that starts on every update and then checks a label used 15 steps over 6 runs. 3 runs stopped at the check and did nothing, using 6 of the 15 steps. The Usage tab shows "15 steps" and nothing more.
  2. A badly ordered flow looks healthy. A flow that edits a work item before checking whether it should stopped at the check, used 3 steps, changed the item anyway, and its run was marked Success. Nothing tells the admin the flow is built in a costly way.
  3. Per-item cost is hard to trace. Branches and scheduled searches cost one step per work item. The audit log shows each action as one line, so an admin can't see where a flow's cost comes from. A daily search over 500 work items would use about 15,000 steps a month on its own.

Also seen: the Usage tab took about two hours to reflect new runs, and one failing web request counted 3 steps where 2 were expected (still investigating).

One idea for the Usage tab

Add one column and a few plain-language flags to the high usage flows table. The flags come from the flow's structure and its run outcomes, both of which Atlassian already has.

What I'm building

Stepmeter is a small open-source tool that does this outside the product today: it reads each flow's structure and run results, shows the wasted steps per flow, explains the cause, and suggests a fix with its saving. The first version works on the test site: see the demo report.

Next, I want it to work from a rules file the admin exports and opens in their own browser, so no access to their site is shared. I haven't confirmed yet that the export contains everything it needs.

Where I'd value your view

  • Do customers ask why their automation costs what it does, or how to reduce it?
  • Is wasted steps the right way to frame it, or is there a better measure?
  • What am I missing about how admins build and run flows at scale?
