Stepmeter for Jira · Vikash Kumar · October 2026

On 3 December, admins will see what their automation costs. They won't see what it wasted.

Per-step billing starts on 3 December, with overage on by default. The Usage tab tells an admin which flows use the most steps. It doesn't tell them how many of those steps did nothing, or why. I think that gap will show up as confused admins and surprise bills, so I tested it.

What I found on a test site

21%
of all steps went to runs that did nothing or failed
40%
of one common flow's steps did nothing
56 / 57
steps I predicted before the Usage tab reported them
  • A wasteful flow can look healthy. One flow changed a work item, then stopped at its check. The audit log marked the run Success. Nothing tells the admin the flow is built in a costly way.
  • The biggest costs are the hardest to trace. Branches and scheduled searches cost a step per work item, but the audit log shows them as one line each.

What I built

A small open-source tool that reads a site's flows and its work item history, then shows for each flow how many steps were wasted, why, and what to change. On my test site, it matched the Usage tab's run count for every event-driven flow, and 89 of 97 steps. The gap was one manual run, which history can't see.

I also have a sketch of how this could fit into the Usage tab itself, using data Atlassian already has. I'd rather walk through that on the call.

What I'd value your view on

  1. Is this a question customers are already asking, or will they only start asking after 3 December?
  2. Is "wasted steps" the right way to frame it?
  3. What am I missing about how large customers build flows?
